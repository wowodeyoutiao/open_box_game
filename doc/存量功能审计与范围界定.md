
### 真实的多余代码（只有一处）

```text
TaskService.GetAll(LocalRole role)   ← 定义了，全工程 0 处调用
```

删掉即可，其它没有发现死代码。

### 占位但必要的（不能删）

```text
ActivityService 的 8 个 HTTP 空响应
  → 客户端启动会请求 /v1/activity/listall、/v1/sign/list、/v1/privilege/list 等，
    不返回会崩，必须占位

PartnerService.GetList
  → 登录后客户端立刻请求 C2S_PartnerList，不返回会卡加载

PlayerService.GetPvpInfo / GetDailyMapInfo
  → 界面打开会请求，空响应防崩

GamePlayLocalHandlers 里伙伴/宠物的 RegUnsupported
  → 明确返回失败，避免"假成功"导致本地状态错乱
```

这些不是"多余逻辑"，是**必要的防御**，而且已经写死为不实现，后续不会往里堆逻辑。

## 五、真正的问题：漏了伙伴

`module 13 伙伴（召唤+技能）openlevel = 10`，玩家当前 18 级。

现状：

```text
PartnerService          只有 GetList，返回 LocalData.Partners（空的）
C2S_PartnerCombat        RegUnsupported
C2S_PartnerCompose       RegUnsupported
C2S_PartnerDisassemble   RegUnsupported
C2S_PartnerReforge       RegUnsupported
C2S_PartnerReplace       RegUnsupported
C2S_PartnerRest          RegUnsupported
C2S_PartnerStar          RegUnsupported
C2S_UpgradeLevel(伙伴)   返回「单机版暂不支持伙伴升级」
```

也就是说：**玩家 10 级就解锁了伙伴，现在 18 级，点进去全是"单机版尚未实现该功能"。**

这比被动技能属性更要紧——属性差一点玩家不容易察觉，但点开整个界面不能用是一眼就看出来的。

### 顺带确认：之前做的技能形状分支不是白做

我上一轮说「斩杀/嘲讽/护盾/这些用不到」——错的。
它们正是伙伴技能。等伙伴系统接入后：

```text
  51 护盾 / 52 践踏 / 58 嘲讽 → 自身方框
  57 斩杀 → 已实现 SpecialEffect.Slay 判定
  61 毁伤 / 65 灭世 / 66 出血 → 自身方框
所以伙伴技能一接，形状和伤害直接能跑
```

## 六、以后的范围规则（写死，不再凭感觉）

### 判据优先级

```text
1. config.xml 里有这个 <module> 吗？         没有 → 不做
2. 对应 openlevel 到了吗？                   没到 → 排后面，不提前做
3. 配置表有实际数据吗？                       没有 → 不做
4. 客户端有 UI 入口吗？                       没有 → 不做
```

### 明确要做的（按 module + 等级）

```text
已完成  Lv1   开箱/任务/包裹/装备/技能/邮件/升级/挂机/系统
已完成  Lv10  战役
待做    Lv10  伙伴（召唤 + 技能 + 上阵）
待做    Lv20  经验池、伙伴升星、首领
待做    Lv30  试炼塔
待做    Lv40  装备强化、装备升星、技能进阶、魂石、副本群
待做    Lv43  遗迹
待做    Lv50  守卫海岛
后期    Lv40+ 世界boss、一战到底、1V1、多V多、家族
```

### 明确不做的

```text
服务端存在但 config.xml 没有对应 module 的：
  跨服 / 排行榜跑马灯 / 运营统计 / 分线 / 跨服匹配
  旧玩法残留：PVEWarMap(2)、SoloTowerMap 的部分分支、logic_mow 的守卫海岛旧字段
```

### 代码层面的规矩

```text
1. 不为了「完整」去实现当前 openlevel 没到的玩法
2. 占位接口只写空响应/明确失败，不写半成品逻辑
3. 新增 Service 前先确认 module ID 和 openlevel
4. BattleService 这类内核可以保留用不到的形状分支（成本是一个 switch case），
   但不要往里加用不到的机制（比如 Buff 全套）
```

## 七、修正后的下一步

原计划「P1-a 被动技能属性接入」**降级**，理由：被动技能门槛是 Lv20/60/100，
当前玩家 18 级，20 级才解锁第一个 `[灵活]`。

**真正该优先做的是伙伴系统**：

```text
已解锁（Lv10）、玩家已 18 级、整块界面点不进去
PartnerService 只有 GetList
所有伙伴协议都是 RegUnsupported
任务里已有 UNLOCK_PARTNER_SLOT / UPGRADE_ANY_PARTNER_LEVEL 类型目标
```

伙伴系统范围建议（最小可用）：

```text
1. 伙伴列表 + 上阵（C2S_PartnerList / C2S_PartnerCombat / C2S_PartnerReplace）
2. 伙伴升级（C2S_UpgradeLevel 支持 ObjectType.PARTNER）
3. 伙伴升星（C2S_PartnerStar）
4. 伙伴技能（按 prof 11/12/13 自动学，BattleService 已有形状支持）
5. 战斗里伙伴 AI（跟随 + 普攻 + 技能）
```

暂不做：

```text
伙伴重构（Reforge）/ 分解（Disassemble）/ 合成（Compose）—— 等召唤系统一起
```
